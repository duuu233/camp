# 本地图片与微信分包

固定图片全部随小程序发布，列表、放大预览、转发与客服卡片均使用本地路径。微信登录仍使用 quickLogin 云函数；图片展示和头像保存不使用云存储。

## 资源归属

| 包 | 内容 |
| --- | --- |
| 主包 | 首页、我的、租赁说明、协议；3 张品牌图、客服二维码、首页前 4 张套餐海报和交付卡 |
| `pages/packages` | 设备页、8/10/15 人海报及设备价目图 |
| `pages/ingredients` | 食材页及 9 张套餐海报 |

两个分包保留原页面路径。首页使用的海报保留在主包，设备页共用，不跨包引用分包私有图片。各包均应小于 2 MiB；食材包空间较紧，添加图片后必须重新检查。

## 图片维护

- `data/campData.js` 统一映射本地资源路径。
- Logo 使用透明 PNG；设备海报使用 JPEG 品质 85，保持原有 1080 像素宽度（价目图原宽 1024）；交付卡最大宽 1200；食材图宽 1000、JPEG 品质 75；二维码保留原文件。
- 每张海报的展示与放大预览共用同一张压缩本地图，避免在包内重复存储两套图片。
- 本次迁移原图保存在 `.asset-originals/`，含下载清单与压缩报告。此目录被 Git 忽略且不进入发行包，应单独备份。压缩后的正式图片纳入版本管理。
- 若本机原图齐全，运行 `pwsh -File tools/compress-assets.ps1` 可重新生成。其他机器可直接使用仓库中的压缩图片构建，无需下载原图或访问云存储。

## 构建与核验

```powershell
# 默认使用 D:/Program Files/HBuilderX；其他安装位置设置 HBUILDERX_PATH。
node tools/build-weixin.mjs
node --test tests/local-images.test.mjs
node tools/check-local-assets.mjs
```

也可在 HBuilderX 中发行微信小程序。输出目录为 `unpackage/dist/build/mp-weixin`。检查脚本核验全部图片、原路由、首页资源归属、云图片 API 残留和每包文件总大小。最终上传体积以微信开发者工具结果为准。

本次发行构建核验：主包 1,393,288 字节（1.329 MiB），设备包 824,935 字节（0.787 MiB），食材包 1,903,240 字节（1.815 MiB）。22 张本地图片、7 个页面路由、3 项自动化单元测试均通过；抽查了压缩后的食材文字、设备价目图与透明 Logo。

模拟器验证尚未完成：本机微信开发者工具关闭了服务端口，CLI 返回 `IDE service port disabled`。未更改该安全设置，也未上传或发布小程序。开启服务端口后，可安装官方测试库并运行已准备的模拟器脚本：

```powershell
npm install --prefix .asset-qa --no-audit --no-fund miniprogram-automator
# 用微信开发者工具 cli.bat 启动 auto 模式，指定发行目录和 --auto-port 9420。
```

模拟器脚本检查四个主要页面中的本地图片解码并截图；分享实际发送、头像选择和真机放大预览仍需在微信中验证。

## 用户头像

用户选择的头像复制到微信本地用户目录，路径与昵称保存在本机登录资料中。重新选择时清理旧头像，退出登录时清理当前头像。旧的云端头像和已失效的临时文件回退到本地默认头像。头像不跨设备同步，清理小程序数据后需重新设置。

## 云端旧文件

此次迁移只移除了代码依赖，没有删除云存储里的旧文件。存量文件仍可能产生存储费用；上线并确认旧版本影响后，再单独清理云端图片。不要直接关闭仍用于微信登录的云环境。
